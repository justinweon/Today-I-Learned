# Pydantic 정리

## 타입 힌트 vs Pydantic

- **타입 힌트** = 그냥 메모. 실행 중엔 아무 효력 없음
- **Pydantic** = 실제로 막아주는 문지기. 틀리면 즉시 터짐

## BaseModel

```python
class Book(BaseModel):  # 이 순간 검증 능력 생김
    title: str = Field(..., min_length=2)   # ... = 필수
    price: int = Field(default=None, gt=0)  # default = 선택
```

## field_validator vs model_validator

- **field_validator** → 필드 1개만 보면 판단 가능할 때
- **model_validator** → 여러 필드 비교해야 할 때 (field 검사 다 끝난 후 실행) mode="before"는 검증 전 샤워시키기. mode="after"는 검증 후 운영하고 싶은 것.

```
사용자 데이터 → field_validator → model_validator → 완성
```

> model_validator가 field_validator를 실행하는 게 아님. Pydantic이 둘 다 순서대로 실행하는 것

## Generic[T] — 공통 응답 틀

```python
T = TypeVar("T")  # 빈칸 예약

class APIResponse(BaseModel, Generic[T]):
    success: bool
    data: Optional[T] = None  # 빈칸
    error: Optional[str] = None

# 쓸 때 빈칸에 끼우기
response_model=APIResponse[BookResponse]        # 단건
response_model=APIResponse[List[BookResponse]]  # 여러개
```

모든 API 응답이 `{ success, data, error }` 로 통일됨
